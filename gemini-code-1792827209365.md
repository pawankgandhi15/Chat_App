## 1. Complete Project Discussion & Architecture Decision Log (Chat History)

This section captures the complete Q&A and architectural trade-offs from our planning session. Use these points when explaining your system design in technical interviews.

### Turn 1: Designing a DevOps Project for the AWS Free Tier
* **User Prompt:** *"I want to create a DevOps project from the AWS free account using technologies like Docker, Kubernetes, CI/CD pipeline, Terraform and like this, so give me the idea for that project."*
* **Key Architectural Insight:**
  * **Why Avoid Amazon EKS:** AWS charges **$0.10/hour (~$73/month)** just for the EKS control plane, which is **not** covered by the legacy Free Tier and rapidly drains credits.
  * **Why Avoid Heavy Self-Hosted CI Servers:** Running Jenkins or GitLab on a separate EC2 instance consumes extra RAM and doubles your public IPv4/EC2 hours. Using **GitHub Actions** (2,000 free build minutes/month) + **Trivy** (container vulnerability scanner) + **Terraform** keeps CI/CD completely off your EC2 bill.

### Turn 2: Choosing a Real-Time Chat Application as the Core Workload
* **User Prompt:** *"We can make a chat application or not?"*
* **Key Architectural Insight:**
  * **Why a Baatchit Beats a CRUD App in Interviews:** Most student portfolios only deploy stateless HTTP (`GET`/`POST`) apps. A real-time Baatchit requires persistent **WebSocket (`ws://`) connections** and solves the **Multi-Container State Synchronization Problem**:
    * If you scale your backend to **2 containers** behind a load balancer for high availability, **User A** might connect to `Backend Container 1` while **User B** connects to `Backend Container 2`.
    * Without a shared message bus, User A's messages are trapped on `Container 1` and never reach User B.
    * Introducing a **Redis Pub/Sub** container on an internal Docker network allows every backend replica to broadcast messages to all other replicas in sub-millisecond latency.

### Turn 3: Verifying 100% Zero-Cost Execution on AWS Free Tier
* **User Prompt:** *"We can make this or not from the AWS Free Tier account?"*
* **Key Architectural Insight:**
  * **New AWS Accounts (Post-July 2025 Free Plan):** Provide **$100 in immediate signup credits** + up to **$100 in bonus credits** ($20 each for 5 onboarding tasks like setting up an AWS Cost Budget). Choosing the **Free Plan** ensures AWS never bills your credit card.
  * **Legacy 12-Month Free Tier Accounts:** Provide **750 hours/month** of `t2.micro` or `t3.micro` compute, **30 GB** of EBS storage, and **5 GB** of S3 storage.
  * **The Terraform Teardown Habit:** By provisioning everything via `terraform apply` and tearing it down with `terraform destroy` when you finish working for the day, your server runs only a few hours per session—costing $0 out of pocket.

### Turn 4: Pivoting to a "Docker-Only" Runtime Architecture
* **User Prompt:** *"Make a proper plan for it, and one more thing: this project should run in Docker only for this."*
* **Key Architectural Insight:**
  * **Why Docker-Only (`Docker Engine` + `Docker Compose v2`) Is Ideal for `t3.micro`:**
    * Running Kubernetes (even lightweight K3s) consumes ~450 MB of your 1,024 MB RAM before deploying a single application container.
    * By using **Docker Compose v2 (`--scale backend=2`)** paired with an **Nginx Reverse Proxy container**, the entire 5-container stack consumes **only ~155 MB of RAM**, leaving over **850 MB of free memory** on your `t3.micro` instance.
    * You still get horizontal scaling, round-robin load balancing via Docker's embedded DNS (`127.0.0.11`), container healthchecks, and automated CI/CD rollouts.

### 4.2 FastAPI WebSocket + Redis Pub/Sub Server (`backend/app/main.py`)
Create an empty `backend/app/__init__.py` file, then create `backend/app/main.py`:

```python
import asyncio
import json
import os
import socket
from datetime import datetime, timezone
from fastapi import FastAPI, WebSocket, WebSocketDisconnect
import redis.asyncio as redis

app = FastAPI(title="Docker-Only Distributed Chat API")

REDIS_URL = os.getenv("REDIS_URL", "redis://redis:6379/0")
CONTAINER_ID = socket.gethostname()  # Unique Docker Container ID (e.g., 8f3c2a1b9d0e)
CHANNEL_NAME = "global_chat_channel"


class ConnectionManager:
    def __init__(self):
        self.active_connections: list[WebSocket] = []

    async def connect(self, websocket: WebSocket):
        await websocket.accept()
        self.active_connections.append(websocket)

    def disconnect(self, websocket: WebSocket):
        if websocket in self.active_connections:
            self.active_connections.remove(websocket)

    async def broadcast_local(self, message: str):
        for connection in list(self.active_connections):
            try:
                await connection.send_text(message)
            except Exception:
                self.disconnect(connection)


manager = ConnectionManager()


async def redis_listener():
    """Listens to Redis Pub/Sub and forwards messages to clients connected to THIS container."""
    while True:
        try:
            r = redis.from_url(REDIS_URL, decode_responses=True)
            pubsub = r.pubsub()
            await pubsub.subscribe(CHANNEL_NAME)
            async for event in pubsub.listen():
                if event["type"] == "message":
                    await manager.broadcast_local(event["data"])
        except Exception as e:
            print(f"[{CONTAINER_ID}] Redis connection retrying: {e}")
            await asyncio.sleep(2)


@app.on_event("startup")
async def startup_event():
    asyncio.create_task(redis_listener())


@app.get("/health")
async def health_check():
    """Health check endpoint for Docker Compose and load-balancing verification."""
    return {
        "status": "healthy",
        "container_id": CONTAINER_ID,
        "timestamp": datetime.now(timezone.utc).isoformat()
    }


@app.websocket("/ws/{username}")
async def websocket_endpoint(websocket: WebSocket, username: str):
    await manager.connect(websocket)
    r = redis.from_url(REDIS_URL, decode_responses=True)

    join_event = json.dumps({
        "type": "system",
        "user": username,
        "text": f"{username} joined via Backend Container [{CONTAINER_ID}]",
        "container_id": CONTAINER_ID,
        "time": datetime.now(timezone.utc).strftime("%H:%M:%S UTC")
    })
    await r.publish(CHANNEL_NAME, join_event)

    try:
        while True:
            raw_text = await websocket.receive_text()
            chat_event = json.dumps({
                "type": "chat",
                "user": username,
                "text": raw_text,
                "container_id": CONTAINER_ID,
                "time": datetime.now(timezone.utc).strftime("%H:%M:%S UTC")
            })
            await r.publish(CHANNEL_NAME, chat_event)
    except WebSocketDisconnect:
        manager.disconnect(websocket)
        leave_event = json.dumps({
            "type": "system",
            "user": username,
            "text": f"{username} disconnected from [{CONTAINER_ID}]",
            "container_id": CONTAINER_ID,
            "time": datetime.now(timezone.utc).strftime("%H:%M:%S UTC")
        })
        await r.publish(CHANNEL_NAME, leave_event)
    finally:
        await r.aclose()
```

### 4.4 Hardened Multi-Stage Backend Dockerfile (`backend/Dockerfile`)
```dockerfile
# Stage 1: Build wheels to keep compilers out of the final runtime image
FROM python:3.11-slim AS builder

WORKDIR /build
RUN apt-get update && apt-get install -y --no-install-recommends gcc && rm -rf /var/lib/apt/lists/*
COPY requirements.txt .
RUN pip wheel --no-cache-dir --no-deps --wheel-dir /build/wheels -r requirements.txt

# Stage 2: Minimal production runtime
FROM python:3.11-slim

WORKDIR /app

# Install curl for Docker healthchecks and create a non-root user
RUN apt-get update && apt-get install -y --no-install-recommends curl \
    && rm -rf /var/lib/apt/lists/* \
    && adduser --disabled-password --gecos "" appuser

COPY --from=builder /build/wheels /wheels
RUN pip install --no-cache-dir /wheels/* && rm -rf /wheels

COPY ./app ./app

# Run as non-root user for Trivy DevSecOps compliance
USER appuser

EXPOSE 8000

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## 5. Phase 2: Docker Compose Orchestration & Nginx WebSocket Load Balancing

### 5.1 Nginx Reverse Proxy Configuration (`nginx/nginx.conf`)
```nginx
events {
    worker_connections 1024;
}

http {
    # Embedded Docker DNS server resolves "backend" across all scaled container replicas
    resolver 127.0.0.11 valid=5s;

    upstream backend_servers {
        server backend:8000;
    }

    upstream frontend_server {
        server frontend:80;
    }

    map $http_upgrade$connection_upgrade {
        default upgrade;
        ''      close;
    }

    server {
        listen 80;

        # Refresh /health in browser to see container_id alternate between Backend #1 and #2
        location /health {
            proxy_pass http://backend_servers/health;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
        }

        # Persistent WebSocket proxy with 1-hour timeout
        location /ws/ {
            proxy_pass http://backend_servers;
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection $connection_upgrade;
            proxy_set_header Host $host;
            proxy_read_timeout 3600s;
            proxy_send_timeout 3600s;
        }

        # Static Frontend UI
        location / {
            proxy_pass http://frontend_server;
            proxy_set_header Host $host;
        }
    }
}
```

## 7. Phase 4: CI/CD & DevSecOps Pipeline with GitHub Actions & Trivy

### 7.1 Configure GitHub Actions Secrets
Go to your GitHub repo -> **Settings -> Secrets and variables -> Actions** and add:
* `DOCKER_USERNAME`: Your DockerHub username
* `DOCKER_PASSWORD`: Your DockerHub Access Token
* `EC2_HOST`: The `ec2_public_ip` output from Terraform
* `EC2_SSH_KEY`: Your private SSH key (`cat ~/.ssh/id_ed25519`)

### 7.2 Workflow File (`.github/workflows/deploy.yml`)
```yaml
name: CI/CD - Build, Trivy Scan & Deploy to AWS EC2

on:
  push:
    branches:
      - main

jobs:
  test-build-scan-deploy:
    runs-on: ubuntu-latest

    steps:
      - name: 1. Checkout Code
        uses: actions/checkout@v4

      - name: 2. Set up Python 3.11 & Run Unit Tests
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - name: Install Dependencies & Run Pytest
        working-directory: ./backend
        run: |
          pip install -r requirements.txt
          pytest

      - name: 3. Log in to DockerHub
        uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_PASSWORD }}

      - name: 4. Build Multi-Stage Docker Images
        run: |
          docker build -t ${{ secrets.DOCKER_USERNAME }}/realtime-baatchit-backend:${{ github.sha }} \
                       -t ${{ secrets.DOCKER_USERNAME }}/realtime-baatchit-backend:latest ./backend
          docker build -t ${{ secrets.DOCKER_USERNAME }}/realtime-baatchit-frontend:${{ github.sha }} \
                       -t ${{ secrets.DOCKER_USERNAME }}/realtime-baatchit-frontend:latest ./frontend

      - name: 5. DevSecOps - Trivy Vulnerability Scan
        uses: aquasecurity/trivy-action@0.35.0
        with:
          image-ref: "${{ secrets.DOCKER_USERNAME }}/realtime-baatchit-backend:latest"
          format: "table"
          exit-code: "1"
          ignore-unfixed: true
          vuln-type: "os,library"
          severity: "CRITICAL,HIGH"

      - name: 6. Push Verified Images to DockerHub
        run: |
          docker push ${{ secrets.DOCKER_USERNAME }}/realtime-baatchit-backend:${{ github.sha }}
          docker push ${{ secrets.DOCKER_USERNAME }}/realtime-baatchit-backend:latest
          docker push ${{ secrets.DOCKER_USERNAME }}/realtime-baatchit-frontend:${{ github.sha }}
          docker push ${{ secrets.DOCKER_USERNAME }}/realtime-baatchit-frontend:latest

      - name: 7. Copy Compose & Nginx Configs to EC2 via SCP
        uses: appleboy/scp-action@v0.1.7
        with:
          host: ${{ secrets.EC2_HOST }}
          username: ubuntu
          key: ${{ secrets.EC2_SSH_KEY }}
          source: "docker-compose.prod.yml,nginx/nginx.conf"
          target: "/home/ubuntu/baatchit"

      - name: 8. Deploy Scaled Containers on EC2 via SSH
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.EC2_HOST }}
          username: ubuntu
          key: ${{ secrets.EC2_SSH_KEY }}
          script: |
            cd /home/ubuntu/baatchit
            export DOCKER_USERNAME=${{ secrets.DOCKER_USERNAME }}
            docker compose -f docker-compose.prod.yml pull
            docker compose -f docker-compose.prod.yml up -d --scale backend=2 --remove-orphans
            docker image prune -f
```

## 8. Phase 5: Local Testing, Cloud Verification & Zero-Cost Teardown

### 8.1 Run Locally on Your Laptop
```bash
docker compose up --build -d --scale backend=2
```
* Visit `http://localhost/health` and refresh several times to watch `"container_id"` alternate between your 2 FastAPI containers.
* Open `http://localhost` in two browser windows and chat between them in real time.

### 8.2 Deploy Infrastructure to AWS
```bash
cd terraform
terraform init
terraform apply -auto-approve
```

### 8.3 Verify Container Memory on EC2
SSH into your EC2 instance (`ssh -i ~/.ssh/id_ed25519 ubuntu@<EC2_PUBLIC_IP>`) and run:
```bash
docker stats
```
You will see all 5 containers (`nginx`, `frontend`, `backend-1`, `backend-2`, `redis`) using **~155 MB / 1,024 MB RAM**.

### 8.4 Zero-Cost Teardown (Run When Finished for the Day)
Always destroy the EC2 environment when you finish coding or demoing so your AWS Free Tier hours and credits remain untouched:
```bash
cd terraform
terraform destroy -auto-approve
```
